Manual de instalación del ambiente de desarrollo

SGE – Sistema de Gestión de Empleados · Autor: David Hidalgo · Noviembre 2026 · Repositorio: github.com/dahidalgor/sge-gestion-empleados

1. Descripción general

El sistema tiene tres partes que se ejecutan en la misma máquina durante el desarrollo:

ComponenteTecnologíaCarpetaDirección
Frontend (interfaz)Vue 3 + Vite, Vue Router, Pinia, Axiosfrontend/http://localhost:5173
Backend (API REST)NestJS, Passport JWT, bcrypt, TypeORM, Swaggerbackend/http://localhost:3000/api
Base de datosPostgreSQL 18 (incluido vía npm: embedded-postgres).pgdata/ + respaldo/localhost:5433

2. Requisitos previos

Solo se necesita Node.js. PostgreSQL no se instala aparte: viene dentro del paquete npm embedded-postgres, que descarga automáticamente la versión correcta para Windows, macOS o Linux.

SoftwareVersiónPara qué se usaComprobar con
Node.js (incluye npm)22 o superior (probado con 26)Ejecutar el sistema, la base de datos y los scriptsnode -v
NavegadorChrome, Edge, Firefox o Safari actualUsar la aplicación–
Editor (opcional)Visual Studio CodeRevisar y modificar el código–

Node.js se descarga de nodejs.org (versión LTS). La primera instalación necesita internet y ocupa alrededor de 700 MB en las carpetas node_modules (PostgreSQL aporta unos 340 MB en macOS y 110 MB en Windows).

3. Obtener el proyecto

El proyecto se entrega en el archivo SGE-gestion-empleados.zip. Basta con descomprimirlo en cualquier carpeta y abrir una terminal (en Windows, PowerShell o CMD) dentro de sge-gestion-empleados/. El zip contiene:

ContenidoPara qué
backend/, frontend/Código fuente del API y de la interfaz
respaldo/sge_empleados.sqlRespaldo de la base de datos con los usuarios y empleados reales del sistema de origen
scripts/Instalación, respaldo, restauración y empaquetado (funcionan en Windows, macOS y Linux)
docs/Este manual y el manual de usuario

No incluye node_modules ni los archivos .env: se generan en el paso 4. El código también está en GitHub (git clone https://github.com/dahidalgor/sge-gestion-empleados.git), pero sin el respaldo de datos.

4. Instalar las dependencias

Desde la carpeta raíz del proyecto (solo la primera vez):

npm run instalar

Ejecuta npm install en la raíz (incluye PostgreSQL), en backend/ y en frontend/, y crea backend/.env y frontend/.env copiando las plantillas .env.example (si ya existen, no se tocan).

5. Variables de entorno

Valores de backend/.env. Solo hay que cambiarlos si se usa un PostgreSQL que ya exista (opción B del paso 6):

VariableValor por defectoSignificado
PORT / FRONTEND_URL3000 / http://localhost:5173Puerto del API y origen permitido por CORS
DB_HOST / DB_PORTlocalhost / 5433Servidor PostgreSQL
DB_USER / DB_PASSWORDpostgres / (vacío)Credenciales de la base de datos
DB_NAMEsge_empleadosNombre de la base de datos
JWT_SECRET / JWT_EXPIRES_IN(texto largo) / 1hClave con la que se firman los tokens (cambiarla en producción) y su duración
SALARIO_BASICO470Salario mínimo aceptado al registrar empleados

frontend/.env solo tiene VITE_API_URL=http://localhost:3000/api.

6. Preparar la base de datos y restaurar el respaldo

Los scripts usan el PostgreSQL que trae npm y se conectan con el driver pg de Node, así que no hacen falta psql ni pg_dump. Elegir una opción:

Opción A – Servidor propio del proyecto (recomendada)

npm run db:crear

Crea un servidor PostgreSQL dentro de la carpeta .pgdata en el puerto 5433 (no afecta a otro PostgreSQL instalado), crea la base sge_empleados y restaura respaldo/sge_empleados.sql. Al final muestra cuántos empleados y usuarios se cargaron.

Atajo: npm run preparar hace los pasos 4 y 6A juntos.

Opción B – Un PostgreSQL que ya exista (opcional)

  1. En backend/.env, poner el puerto real (normalmente DB_PORT=5432) y la contraseña en DB_PASSWORD.
  2. Ejecutar npm run db:restaurar: crea la base si no existe y carga el respaldo.
Los usuarios y sus contraseñas también vienen en el respaldo (cifradas con bcrypt). Solo si no hay respaldo, el API crea la primera vez 2 usuarios y 20 empleados de muestra.

7. Ejecutar el sistema

npm run dev

Enciende la base de la opción A si está apagada (con la opción B usa directamente la de .env) e inicia el API y el frontend en la misma terminal. Ctrl + C los detiene. Por separado: npm run api y npm run web. Para apagar la base de la opción A: npm run db:detener.

8. Comprobar la instalación

  1. Abrir http://localhost:5173 e ingresar con un usuario del sistema de origen (de fábrica: admin / Admin123* o consulta / Consulta123*).
  2. Verificar que el listado de empleados tenga los mismos registros que en la computadora de origen.
  3. Documentación del API (Swagger): http://localhost:3000/api/docs. Pruebas unitarias: npm test.

9. Entregar el proyecto a otra computadora

En la computadora donde el sistema ya funciona, con la base encendida:

npm run empaquetar

Genera un respaldo actualizado de la base (respaldo/sge_empleados.sql) y el archivo entrega/SGE-gestion-empleados.zip con el código, los manuales y ese respaldo. Ese zip es lo que se entrega al siguiente ingeniero, que sigue este manual desde el paso 3.

ComandoQué hace
npm run db:respaldarSolo guarda la base en respaldo/sge_empleados.sql (SQL plano generado con Node; restaura estructura, datos, claves y contadores en una transacción)
npm run db:restaurarCarga el respaldo. Si la base ya tiene empleados se detiene para no borrarlos; para reemplazarlos: npm run db:restaurar -- --forzar
El respaldo contiene datos reales del personal: no se sube a GitHub (está en .gitignore) y el zip debe entregarse por un medio privado.

10. Problemas frecuentes

SíntomaSolución
No se encontró PostgreSQL para este sistemaFalta instalar las dependencias: ejecutar npm run instalar (con internet)
No se pudo conectar con PostgreSQL / ECONNREFUSEDEncender la base (npm run db:iniciar) o corregir DB_PORT y DB_PASSWORD en backend/.env
“La base ya tiene N empleados y el respaldo los reemplazaría”Protección contra pérdida de datos. Usar -- --forzar solo si se quiere reemplazar
EADDRINUSE :3000 o :5173Otro proceso usa el puerto: cerrarlo o cambiar PORT (y VITE_API_URL)
El login dice que no se pudo conectar con el servidorEl API no está corriendo: revisar la terminal de npm run dev

docs/          manuales en PDF y su fuente HTML
