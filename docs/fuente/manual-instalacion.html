Manual de instalación del ambiente de desarrollo

SGE – Sistema de Gestión de Empleados · Autor: David Hidalgo · Noviembre 2026 · Repositorio: github.com/dahidalgor/sge-gestion-empleados

1. Descripción general

El sistema tiene tres partes que se ejecutan en la misma máquina durante el desarrollo:

ComponenteTecnologíaCarpetaDirección
Frontend (interfaz)Vue 3 + Vite, Vue Router, Pinia, Axiosfrontend/http://localhost:5173
Backend (API REST)NestJS, Passport JWT, bcrypt, TypeORM, Swaggerbackend/http://localhost:3000/api
Base de datosPostgreSQL.pgdata/ (opción A)localhost:5433

Node.js se descarga de nodejs.org y PostgreSQL de postgresql.org/download (instalador de EDB para Windows y macOS).

3. Obtener el código fuente

git clone https://github.com/dahidalgor/sge-gestion-empleados.git
cd sge-gestion-empleados

Si se entrega en un archivo .zip, basta con descomprimirlo y abrir una terminal dentro de la carpeta.

4. Instalar las dependencias

Desde la carpeta raíz del proyecto (solo la primera vez):

npm run instalar

Este comando ejecuta npm install en la raíz, en backend/ y en frontend/.

5. Configurar las variables de entorno

Los archivos .env no se suben a GitHub porque contienen secretos. Se crean copiando las plantillas:

cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env

En Windows (PowerShell) se usa copy en lugar de cp. Variables de backend/.env:

VariableValor por defectoSignificado
PORT3000Puerto del API
FRONTEND_URLhttp://localhost:5173Origen permitido por CORS
DB_HOST / DB_PORTlocalhost / 5433Servidor PostgreSQL
DB_USER / DB_PASSWORDpostgres / (vacío)Credenciales de la base de datos
DB_NAMEsge_empleadosNombre de la base de datos
JWT_SECRET(texto largo)Clave con la que se firman los tokens. Debe cambiarse en producción
JWT_EXPIRES_IN1hTiempo de vida del token
SALARIO_BASICO470Salario mínimo aceptado al registrar empleados

frontend/.env solo tiene VITE_API_URL=http://localhost:3000/api, la dirección del API.

6. Preparar la base de datos

Hay dos formas. Basta con elegir una.

Opción A – Servidor local del proyecto (macOS con el instalador de EDB)

Crea un servidor PostgreSQL propio dentro de la carpeta .pgdata, en el puerto 5433, sin afectar a otro PostgreSQL instalado:

npm run db:crear

El script usa los programas de /Library/PostgreSQL/18/bin. Si PostgreSQL está en otra ruta, hay que corregirla en package.json.

Opción B – Un PostgreSQL ya instalado (Windows, Linux o macOS)

  1. Crear la base de datos con pgAdmin o desde la terminal: 
    psql -U postgres -c "CREATE DATABASE sge_empleados;"
  2. En backend/.env, poner el puerto real (normalmente DB_PORT=5432) y la contraseña del usuario en DB_PASSWORD.
  3. Para arrancar, usar los comandos por separado de la sección 7 (npm run api y npm run web), ya que npm run dev intenta encender el servidor de la opción A.

No hace falta crear tablas a mano: al iniciar, el API las crea con TypeORM y carga 2 usuarios y 20 empleados de muestra.

7. Ejecutar el sistema

Todo en una sola terminal (opción A)

npm run dev

Enciende PostgreSQL si está apagado y luego inicia el API y el frontend juntos. Ctrl + C detiene ambos. Para apagar la base de datos: npm run db:detener.

Por separado (opción B, o para ver cada registro aparte)

npm run api     # terminal 1: backend en http://localhost:3000/api
npm run web     # terminal 2: frontend en http://localhost:5173

Con la opción A, antes se enciende la base de datos con npm run db:iniciar.

8. Comprobar la instalación

  1. Abrir http://localhost:5173: debe aparecer la pantalla de inicio de sesión.
  2. Ingresar con un usuario de prueba:
    UsuarioContraseñaRolPermisos
    adminAdmin123*adminver, crear, editar y eliminar
    consultaConsulta123*consultasolo ver
  3. Abrir http://localhost:3000/api/docs: documentación Swagger del API.
  4. Ejecutar las pruebas unitarias del backend (17 pruebas): 
    npm test

9. Problemas frecuentes

SíntomaCausa probableSolución
El API muestra ECONNREFUSED o connect al iniciarPostgreSQL apagado o puerto distintoEncender la base (npm run db:iniciar) o corregir DB_PORT en backend/.env
password authentication failedContraseña incorrecta en .envPoner la contraseña del usuario postgres en DB_PASSWORD
database "sge_empleados" does not existNo se creó la baseEjecutar el paso 1 de la opción B
EADDRINUSE :3000 o :5173El puerto ya está ocupadoCerrar el otro proceso o cambiar PORT (y VITE_API_URL)
La pantalla de login dice que no se pudo conectar con el servidorEl API no está corriendoRevisar la terminal del API e iniciarlo con npm run api
initdb: command not found o ruta inexistentePostgreSQL instalado en otra carpetaUsar la opción B o corregir la ruta en package.json

10. Estructura del proyecto

backend/src/
  auth/        login, generación y validación del JWT, roles
  usuarios/    entidad y servicio de usuarios (contraseñas con bcrypt)
  empleados/   entidad, DTOs, reglas de negocio, servicio y controlador del CRUD
  seed/        datos de muestra
frontend/src/
  views/       Login, Panel, Empleados, Sesión JWT
  components/  formulario de empleado, diálogo de confirmación, avisos
  services/    cliente Axios que envía el token en cada petición
  stores/      estado de la sesión (Pinia)
  router/      rutas protegidas por la sesión
